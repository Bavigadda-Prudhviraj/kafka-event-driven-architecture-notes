                                                                              Lets focus on, Stateful Processing Nodes

A stateful processing node is a node that must remember information from previous records to produce correct output.
Stateful operations usestate stores (RocksDB) to store intermediate state.
Common examples:

     Count records per key
     Sum amounts per user

     2 major responsibility of GroupbyKey and GroupBy:
     1. Convert KStream -----> KGroupedStream
     This tells downstream stateful operations which key to use for aggregation (either existing key or some new key)
     2. Repartition if required.
     When key is changed, then it initiate the reparation.

                                                         1. groupByKey

      · groupByKeytells downstream stateful operations to use existing key for aggregation.
      · Use it when the current key is already the key you want for aggregation.

 //optional, say in case you want to change the key, else if not don't use selectKey
 KStream<String, Order> ordersByUser = orders.selectKey((orderId, order) -> order.getUserId());
 KGroupedStream<String, Order> groupedOrders = ordersByUser.groupByKey();

               This is not a normal Stream, it has method for aggregation like count, aggregate etc.

                                                           2. groupBy

   groupBysays, I don't want to use the current key, I will tell you a new key (which could be of different type too)

        KGroupedStream<String, Order> groupedOrders = orders.groupBy((orderId, order) -> order.getUserId());

For both groupByKey and groupBy, if there is change in Key, Kafka Streams needs to redistribute records (re-partition)
according to the new key.

                                           5. KStream - KTable Join
AKStream-KTablejoin enriches each stream event with the latest value from a table.

KStream<K, VR> join(KTable<K, VT> table, ValueJoiner<? super V, ? super VT, ? extends VR> joiner);

                                                              KStream value  Latest value for the key
                                                                             from KTable

Enriched Output

KStream<String, Order> ordersByUser = orders.selectKey((orderId, order) -> order.getUserId());

KTable<String, UserProfile> users = builder.table( "users",
                                                           Consumed.with(Serdes.String(), userProfileSerde),
                                                           Materialized .<String, UserProfile, KeyValueStore<Bytes, byte[]>>as("users-store")
                                                                  .withKeySerde(Serdes.String())
                                                                  .withValueSerde(userProfileSerde)

                                                       );

KStream<String, EnrichedOrder> enrichedOrders = ordersByUser.join(
                                                                      users,
                                                                      (order, user) -> new EnrichedOrder(order, user)

                                                                 );
Note:
Key for both KStream and KTable should be same.

                                    Example:
                                    User table:
                                    Key Value
                                    u1 { name: "Asha", city: "Delhi" }
                                    u2 { name: "Ravi", city: "Pune" }
                                    Order stream:
                                    Key Value
                                    u1 { orderId: "o1", userId: "u1", amount: 500 }
                                    Output:
                                    Key Value
                                    u1 { orderId: "o1", userId: "u1", amount: 500, name: "Asha", city: "Delhi" }
