                                                        SerDes:

             SerDes = Serializer + Deserializer combined into 1 object

             SERIALIZER: Java Object ----> bytes
             DESERIALIZER: bytes ----> Java Object

             SERDE: Both in one package

                                            What's the need?

Kafka stores data in bytes
RocksDB stores data in bytes

So whenever we need to:
· Read data from Kafka topic or RocksDB, we need Deserialization (bytes to Java Object)

   and
· Write data to Kafka topic or RocksDB, we need Serialization (Java Object to bytes)

So 5 places within topology where we need SerDes:

· Source: we need to read from Kafka topic, so we need Deserialization.

· Sink: we need to write to Kafka topic, so we need Serialization.

· Repartition (Sub-topology): we need to write to Kafka topic, so we need Serialization.

· RocksDB Write:
        · Like when we use KTable, GlobalKTable we need Serialization.
        · Or processor nodes like count etc, which need to store data in RocksDB.

· RocksDB Read:
        · Like when we do JOIN, we read from RocksDB, so we need Deserialization.

import com.fasterxml.jackson.databind.ObjectMapper;                              Payment
import org.apache.kafka.common.serialization.Serializer;                         Etc.

public class JsonSerializer<T> implements Serializer<T> {

       private final ObjectMapper objectMapper = new ObjectMapper();

       @Override
       public byte[] serialize(String topic, T data) {

              if (data == null) {
                   return null;

              }
              try {

                      return objectMapper.writeValueAsBytes(data);
              }
              catch (Exception e) {

                          throw new RuntimeException("Error serializing", e);
                  }
       }
}

                                                    2. Deserializer              Our Serializer is generic means it can accept
                                                                                 any Object.
import com.fasterxml.jackson.databind.ObjectMapper;                              So during Deserialization, we need to know
import org.apache.kafka.common.serialization.Deserializer;                       the object type in which we need to convert.

public class JsonDeserializer<T> implements Deserializer<T> {

       private final ObjectMapper objectMapper = new ObjectMapper();

       private final Class<T> targetType;

           public JsonDeserializer(Class<T> targetType) {
                  this.targetType = targetType;

           }

           @Override
           public T deserialize(String topic, byte[] data) {

                  if (data == null) {
                      return null;

                  }
                  try {

                          return objectMapper.readValue(data, targetType);
                  } catch (Exception e) {

                          throw new RuntimeException("Error deserializing", e);
                  }
           }
}

public class JsonSerde<T> implements Serde<T> {                                  JsonSerde class already present in framework,

   private final JsonDeserializer<T> deserializer;

       this.serializer = new JsonSerializer<>();

   @Override
   public JsonSerializer<T> serializer() {

   @Override

                Now 1 more doubt might have come:
                What will happen if Serialization, Deserialization fails in Kafka Stream?

        Deserialization fails                                                                                 Serialization fails

         UseCase1: Wrong serde type                                                                        UseCase 1: Wrong output serde
         Topic has: {"orderId": "001", "amount": 150 } (JSON string)                                       We have: Long value
         We read: Consumed.with(Serdes.String(), Serdes.Long())                                            We write: Produced.with(Serdes.String(), Serdes.String())
         Result: Tries to read JSON bytes as 8-byte Long --> EXCEPTION                                     Result: Tries to serialize Long as String --> ClassCastException
         UseCase2: Corrupted data                                                                          UseCase 2: Object can't be serialized
         Topic has: some garbage bytes that aren't valid JSON                                              We have: Order object with a circular reference
         We read: Consumed.with(Serdes.String(), new JsonSerde<>(Order.class))                             We write: JsonSerde<>(Order.class)
         Result: Jackson can't parse --> JsonParseException --> EXCEPTION                                  Result: Jackson can't serialize  JsonMappingException
