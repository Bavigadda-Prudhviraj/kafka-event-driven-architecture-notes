                                   · Its not a separate cluster or infrastructure.

                                             Topology:

       · It's a logical flow of how data moves and get processed from source Topics to sink Topics.
       · This flow is like a DAG (Directed Acyclic Graph), data flow in one direction, no loops and cycles.
       · We defined it once during application startup, after that Kafka Stream execute it forever.

                                    Stateless Processing:

       like raw material            Source:                · Entry point, read records from 1 or more Kafka Topics
                                                           · No parent processor
                                    Topic "order-events"   · Deserialize bytes to Key-value pairs
                                                           · Forward records to its child processors
       like                         PROCESSORS
        · cut,                                             · Business logic where transformation happens.
        · paint,                                           · Receive record from parent processor and process them
        · package etc.                                     · Forward results to child processors

like Shipping of finished material      Sink:               · Exit point, writes records to a Kafka Topic
                                    Output Topic            · No child processor
                                                            · Serialize key-value to bytes
                                                            · Write to output topic

                                    Stateful Processing:                               For stateful processing, Kafka Streams stores data
                                                                                       locally in RocksDB and keeps it fault-tolerant through
                                           Source:                                     changelog topics
                                    Topic "order-events"

                                       PROCESSORS          RocksDB

                                               Now 1 doubt might have comes:

       RocksDB is nothing but a Key-value file(database) store
       on Disk.
       and
       Each Kafka Task maintained its own RocksDB state.

       Now a doubt might have come is, what happens when

       machine dies or rebalance occurs?

       Since RocksDB is local to a particular machine, the

       task may get assigned to another instance that does

       not have that local state.                 Then?

                                   That's where changelog Topic comes into the picture.

       So, whenever a Task update its RocksDB. It also publish an
       event in changelog topic, this topic is internally created by
       Kafka Stream framework itself.

       So when the task moves to another instance (due to
       rebalance) or original machine is lost, Kafka Stream create
       a new RocksDB store and restore its state by replaying
       records from the changelog topic.

package com.eda.streams.config;                                                           public class Order{
import com.eda.streams.model.Order;                                                       private String orderId;
import com.fasterxml.jackson.databind.ObjectMapper;                                       private String customerId;
import org.apache.kafka.common.serialization.Deserializer;                                private String productId;
import org.apache.kafka.common.serialization.Serde;                                       private Integer quantity;
import org.apache.kafka.common.serialization.Serdes;                                      private Double totalAmount;
import org.apache.kafka.common.serialization.Serializer;                                  private String status;
import org.apache.kafka.streams.StreamsBuilder;
import org.apache.kafka.streams.kstream.*;                                                    //getters and setters
import org.springframework.context.annotation.Bean;
import org.springframework.context.annotation.Configuration;                              }

@Configuration
public class OrderStreamTopology {
private static final ObjectMapper objectMapper = new
ObjectMapper();

@Bean
public void orderCountTopology(StreamsBuilder builder) {

         // SOURCE: read from "order-events" as raw JSON
         strings
         KStream<String, String> orderStream =
         builder.stream("order-events",
         Consumed.with(Serdes.String(), Serdes.String()));

         // FILTER: only orders with totalAmount > 100
         KStream<String, String> highValueOrders =
         orderStream.filter((key, value) -> {
         try {

                  Order order = objectMapper.readValue(value,
                  Order.class);
                  return order.getTotalAmount() != null &&
                  order.getTotalAmount() > 100;
                  } catch (Exception e) {

                      return false;
                  }
             });

         // Re-key by productId
         // This will trigger a REPARTITION topic
         KStream<String, String> productKeyedOrders =

                  highValueOrders.selectKey((oldKey, value) -> {
                  try {

                           Order order =
                           objectMapper.readValue(value,
                           Order.class);
                           return order.getProductId();
                      } catch (Exception e) {
                           return "UNKNOWN";
                      }
             });

      //RocksDB store name
      KTable<String, Long> productCounts =

                   productKeyedOrders
               .groupByKey(Grouped.with(

                        Serdes.String(),
                        Serdes.String()))
               .count(Materialized.as("product-count-store"));

      //output topic
      productCounts

               .toStream().mapValues(String::valueOf)
               .to("product-counts",
               Produced.with(Serdes.String(), Serdes.String()));

   }                                             Expectation:

}
