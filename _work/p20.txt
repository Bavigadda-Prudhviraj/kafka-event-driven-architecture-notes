                      What's the use of WINDOW in Kafka Stream:
Kafka streams are infinite. New events keep on arriving. So there is no start, no end.

So, what if our business requirement is to answer: How many orders we received in last 1hr?

Suppose Incoming order events for same key "Ord-1":

10:00 Order-1                  Suppose we are grouping  orders                 State Store (KTable)
10:10 Order-2                  without window:          .groupByKey()
10:30 Order-3                                           .count();               key Count
11:15 Order-4
11:25 Order-5                                                                   Ord-1 5

The KTable only knows:
Orders seen so far = 5.

It does not remember time. Or group orders based on time window.

So, if anyone asks How many orders received between 10:00 - 11:00?

KTable currently can not answer that.

So,
A window is a time-based boundary used to group records from an infinite stream into finite chunks.

Suppose Incoming order events for same key "Ord-1":

Before we proceed further, one doubt might be coming:

By-default in Kafka Stream WINDOW record timestamp is used. What if I want Kafka Stream WINDOW to use Event
time instead of Record timestamp?

                          We can easily do that,
                          By providing custom implemenation of TimestampExtractor interface

                                                 Interface already present in Kafka Stream framework

                                  public interface TimestampExtractor {
                                     long extract(ConsumerRecord<Object, Object> record, long partitionTime);

                                  }

                        public class OrderTimestampExtractor implements TimestampExtractor {

                          @Override
                           public long extract(ConsumerRecord<Object, Object> record, long partitionTime) {

                                 Order order = (Order) record.value();
                                 return order.getCreatedAt().to Instant().toEpochMilli();
                           }
                        }

                                            2. Hopping Windows

· Fixed size and advanced by fixed interval
· Each record may belongs to multiple windows.

Example:
Window size = 10 mins
Advance by = 5 mins

Window Time Range

W1                          10:00 to 10:10

W2                          10:05 to 10:15

W3                          10:10 to 10:20

So event with record timestamp: 10:07 belongs to W1 and W2.

Use-Case:
· Order in last 1hr but updated every x mins.
· Moving traffic count
· Rolling revenue calculation

   etc.
